# 22. Cursor-Based Pagination & Sorting

This use case describes the standardized approach for navigating large datasets across the CloudVault platform.

## Overview

Traditional offset-based pagination (`LIMIT 20 OFFSET 100`) becomes slow as the offset increases and can skip or duplicate items if data is inserted/deleted between page loads. CloudVault uses **Keyset (Cursor) Pagination** to provide a high-performance, stable, and infinite-scroll friendly experience.

## Technical Implementation

### Cursor Parameters (`CursorParams`)

Clients send pagination requests using the following parameters:
- `cursor`: An opaque Base64 string representing the last seen item's sorting value and ID.
- `size`: Number of items to retrieve (default: 20).
- `sortBy`: Field to sort by (e.g., `createdAt`, `name`, `size`).
- `direction`: `ASC` or `DESC`.

### Response Format (`CursorPageResponse`)

The API returns data wrapped in a paging structure:
```json
{
  "content": [...],
  "nextCursor": "Y3JlYXRlZEF0PTE3MTQ0MzUyMDAwMDAsaWQ9NTVmZTFlYmMtYjQ0ZC00ZmRkLWJhMDUtNzhkZmFjN2RlYmI0",
  "hasNext": true
}
```

### Encoding Logic

Cursors are generated by combining the sort field value and the record's unique UUID:
`Base64(fieldValue + "|" + id)`

This ensure that even if multiple records have the same timestamp or name, the cursor remains unique and stable.

## Usage Scenarios

### Infinite Scrolling
1. The frontend fetches the first page without a `cursor`.
2. The backend returns 20 items and a `nextCursor`.
3. When the user reaches the bottom of the list, the frontend makes a new request using the `nextCursor`.
4. This process repeats until `hasNext` is `false`.

### Navigation Stability
If a new file is uploaded while a user is browsing page 2, the cursor-based approach ensures that the user doesn't see the same file again on page 3 (which often happens with offset-based paging).

## Supported Modules
- **Audit Logs**: History of user actions and resource changes.
- **Files**: Listing of files within projects and folders.
- **Folders**: Directory structure navigation.
